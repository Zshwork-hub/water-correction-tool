# UI 回归修复与显示图层解耦设计

状态：用户已确认方向，待规格复核
日期：2026-07-19
分支：`codex/ui-shell-river-page`

## 1. 背景

UI Shell 第一轮真实数据回归确认主工作流基本正常，同时暴露以下问题：

1. 选中像元统一为 `(row, col)` 后，手动写入方向和建议方向仍按旧四元组解包，触发 `ValueError`。
2. Windows `<MouseWheel>` 事件可能把 `event.num` 提供为字符串 `"??"`，侧栏滚动代码直接转整数后持续报错。
3. 编辑模式与显示图层仍绑定，用户不能在流向订正工作流中显示河道骨架，也不便在河道视图中提前选择流向订正对象。
4. Windows 默认 ttk 主题可能忽略按钮背景色，却保留白色前景色，导致选中导航白字白底。
5. 流向页把手动改向、河网辅助和 DEM 审核纵向堆叠，信息层级不清晰。
6. “建议方向”只对当前 FDR 和 8 邻域投票，当前方向权重最高；在原始 FDR 较乱且缺少 DEM 约束时参考价值有限。

本轮目标是修复这些回归并完善交互，不修改河网、周边汇流和 DEM 评分算法。

## 2. 核心决策

### 2.1 编辑目标与显示图层分离

引入两个独立状态：

- `mode_var`：当前编辑目标，取值 `stream` 或 `flow`。
- `display_mode_var`：当前地图底图，取值 `stream` 或 `flow`。

左侧“河道订正/流向订正”只改变 `mode_var`。顶部“显示图层”只改变 `display_mode_var`。切换左侧页面不得自动覆盖用户选择的显示图层。

新增明确接口：

- `get_edit_raster()`：返回写入目标。
- `get_display_raster()`：返回渲染和地图坐标换算目标。
- `can_modify_active_raster()`：仅当编辑目标、显示图层一致且对应栅格已加载时返回真。

迁移期间 `get_active_raster()` 保持为编辑目标别名，避免编辑、历史和项目模块语义变化；渲染、缩放、居中、滚动范围和 `canvas_to_rc()` 改用显示栅格。

### 2.2 不一致时进入只读选择状态

当 `mode_var != display_mode_var` 时：

- 禁止左键单击写入、拖动刷写和沿线方向刷写。
- 禁止“写入所选方向”“按河流线修正”“应用预览”、撤销和重做。
- 所有写入入口必须在业务方法内再次校验，不能只依赖按钮禁用。
- 保留右键单点选择、右键框选、加入/移除订正对象、设置出口、生成预览、DEM 评估、定位和报告导出。
- 选择行为使用当前显示栅格计算行列；加入河道订正对象时仍校验对应位置是否为 `Stream=1`，并检查行列边界。
- 河道页面产生的单点和框选状态在切换到流向页面后保留。

这允许用户在“流向订正 + 显示河道”组合下清楚选择骨架，但不会误改当前不可见的 FDR。

### 2.3 显眼且稳定的只读提示

在顶部命令栏下方保留一条固定高度的模式状态条，避免出现和消失造成布局跳动。

正常状态示例：

`编辑目标：流向 | 显示图层：流向 | 可编辑`

失配状态示例：

`只读选择状态：当前显示河道，编辑目标为流向；切换显示图层后才能写入。`

失配状态使用：

- 浅黄色背景。
- 深棕黄色粗体文字。
- 左侧 `只读` 文本标识。
- 状态条始终横跨主内容区，在河道、流向、显示和历史页面均可见。

触发被禁止的写入操作时，底部状态栏同步显示同一原因，不弹出重复模态窗口。

## 3. 顶部显示图层控件

顶部空余区域增加紧凑控件：

- 标签：`显示图层`
- 只读下拉框：`河道`、`流向`

行为：

- 选择已加载图层后保持当前地图中心和缩放；若两个栅格网格一致，直接重绘。
- 目标图层未加载时不切换，底部状态栏提示先加载对应 ASC。
- 新加载某个 ASC 时，如果当前显示图层未加载，可自动显示新图层；否则保留用户当前显示选择。
- 项目和自动保存增加可选字段 `display_mode`。旧项目缺少该字段时回退到保存的编辑模式，保持向后兼容。

## 4. 选择与“加入所选像元”

统一选中像元数据契约为 `Optional[Tuple[int, int]]`，不再混用 `(row, col, x, y)`。

修复范围：

- `apply_selected_direction()` 只解包 `(row, col)`。
- 所有选择消费者统一调用 `_require_selected_flow_cell()` 或新的纯 helper。
- `add_selected_stream_cell_to_lock()` 增加行列边界检查。
- 右键单点后立即刷新流向辅助按钮状态和选中叠加层。
- 若像元不是 `Stream=1`，状态栏明确显示“所选像元不是有效河道”。
- 若像元已锁定，显示“该像元已在订正对象中”，不静默失败。
- 从河道页面切换到流向页面时保留 `selected_flow_cell` 和 `selected_flow_region`。

## 5. 删除“建议方向”

删除以下用户界面和无效复杂度：

- “建议方向”按钮。
- `CommandId.SUGGEST_FLOW_DIRECTION`。
- `suggest_flow_direction()`。
- `_suggest_flow_candidates()` 及只为该算法使用的导入。
- 对应 tooltip、控件注册表键和测试期望。

保留“写入所选方向”。流向方向辅助继续由河道本体预览、周边汇流预览和 DEM 评估承担。

## 6. 流向页信息架构

流向页内容区改为三个页签，固定 footer 保持不变。

### 6.1 手动改向

仅包含：

- D8 方向选择。
- 写入所选方向。
- 当前选中像元信息。

不再显示建议方向。

### 6.2 河网辅助

按工作顺序组织：

1. 订正对象：加入所选河道、加入所选像元、移除所选河道。
2. 河道本体流向：设置出口、计算模式、预览河道流向。
3. 周边汇流：范围模式、近带、远带、最大距离、预览周边汇流。
4. 汇流范围边界：显示开关、线宽、加入范围内河道，作为折叠的次要设置。

页签底部继续显示流向辅助状态摘要。

### 6.3 DEM 审核

仅包含：

- DEM 加载、缓存生成和取消。
- 当前预览评估。
- 标记显示与阈值参数。
- 逆坡定位和报告导出。
- 缓存状态、评分状态和图例。

DEM 报告按钮必须在该页签内直接可达；内容不足时不显示无意义滚动，内容超高时显示明确滚动条。

### 6.4 固定操作区

流向页 footer 始终保留：

- 应用预览。
- 清除预览。
- 重置辅助状态。

失配只读状态下“应用预览”禁用，其他两个操作仍可用。

## 7. 选中样式修复

不再依赖 Windows 主题可能忽略的深色按钮背景配白字。

左侧导航使用：

- 文字始终保持深色或深蓝，禁止白色前景。
- 当前项使用粗体深蓝文字。
- 当前项左侧增加固定蓝色竖条，竖条使用 `tk.Frame`，不依赖 ttk 按钮背景。
- 未选中项保持普通深色文字。

`Primary.TButton` 同样使用可读的深色文字；背景色作为增强效果，而不是文字可读性的前提。页签选中状态使用系统 ttk Notebook 状态，不覆盖为白色文字。

## 8. 滚轮兼容修复

新增安全整数转换 helper：

- `event.delta` 无法转换时视为 `0`。
- `event.num` 为 `"??"`、空值或其他非数字时视为 `0`。
- Windows `<MouseWheel>` 主要根据 `delta` 归一化。
- Linux `<Button-4>/<Button-5>` 根据有效的 `num` 归一化。
- 单次异常事件不得产生 Tkinter callback traceback。

侧栏仍只在鼠标位于任务面板时临时绑定滚轮，不抢占地图缩放。

## 9. 写入保护范围

以下入口必须调用统一保护函数：

- 左键画笔、橡皮擦和拖动刷写。
- 流向沿线刷写。
- 写入所选方向。
- 河流线批量修正。
- 应用河道流向/周边汇流预览。
- 撤销、重做。

统一保护函数返回布尔值并写入非模态状态提示。预览生成、锁定、选择、快照查看、DEM 评估和导出不受影响。

- `water_tool/water_ui_theme.py`：只读警告和可读选中样式。
- `water_tool/water_ui_components.py`：导航左侧标识、滚轮安全转换。
- `water_tool/water_legacy_pages.py`：流向页三页签布局并删除建议方向。
- `water_tool/water_shell_model.py`：控件注册表更新。
- `water_tool/water_ui_state.py`：显示/编辑一致性派生和按钮状态。

- `water_tool/water_editing.py`：选中像元解包和统一写入保护。

## 11. 测试策略

### 11.1 自动测试

覆盖：

- 二元组选中像元可写入方向，不再抛出解包异常。
- 加入有效 `Stream=1` 单像元、非河道像元、越界像元和已锁定像元。
- Windows `event.num="??"` 与有效 `delta` 的滚轮归一化。
- 编辑/显示一致和不一致的状态派生。
- 所有写入命令在失配时被拒绝，选择和预览仍可用。
- 河道页面选择切换到流向页面后保留。
- 流向页三个页签和固定 footer 控件契约。
- 导航选中样式不使用白色前景。
- `display_mode` 项目/自动保存读写和旧文件回退。

### 11.2 GUI smoke

在 `1366 x 768` 和 `1920 x 1080` 验证：

- 模式状态条持续可见，失配时警告醒目。
- 左侧导航选中文字可读，蓝色竖条清晰。
- 三个流向页签均可达，DEM 报告按钮不被挤出。
- 侧栏滚轮无 traceback，地图滚轮仍缩放。
- 底部应用/清除/重置始终可见。

### 11.3 人工真实数据回归

重点验证：

1. 流向订正 + 显示河道：左键不写入，右键可选择并加入河道骨架。
2. 切换显示流向后，可写入所选方向和应用预览。
3. 河道订正 + 显示流向：河道写入和矢量修正禁用。
4. 切换页面、项目恢复和自动保存恢复后，编辑/显示状态明确且数据不被隐式修改。

## 12. 非目标

本轮不做：

- 不修改河道本体方向算法。
- 不修改近远带、范围 SHP 汇流算法。
- 不修改 DEM 缓存和评分算法。
- 不增加新的自动流向推断。
- 不合并河流线和汇流范围图层。

## 13. 验收标准

- 用户反馈的 Tkinter callback traceback 全部消失。
- “加入所选像元”对有效河道像元有明确成功反馈。
- 显示图层可独立切换，失配时所有栅格写入均被可靠阻止。
- 只读提示显眼、稳定且不遮挡地图或按钮。
- 河道视图选择可跨页面用于流向辅助。
- “建议方向”从产品和代码中移除。
- 流向页三类工作清楚分离，DEM 报告可达。
- 左侧导航和主要按钮在 Windows 主题下文字始终可读。
- 自动测试、编译、GUI smoke 和真实数据回归通过后再合并到 `main`。
