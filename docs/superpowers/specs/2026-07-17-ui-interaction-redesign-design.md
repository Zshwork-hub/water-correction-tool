# 水系订正工具 UI 与交互重构设计

日期：2026-07-17

## 1. 背景

当前软件的河道订正、流向订正、DEM 辅助、项目管理、显示配色和历史恢复功能已经形成完整工作流，但界面仍沿用功能逐步追加时形成的组织方式。

主要问题不是单纯的空间不足，而是：

- 页面按钮数量过多，主要操作和次要操作并列显示。
- 同一能力存在多个名字相近的入口。
- 文件状态、模式提示、任务结果、坐标和警告缺少信息优先级。
- 流向辅助页纵向内容超过可用高度，动态提示会将底部 DEM 按钮裁出界面。
- 顶部工作模式、右侧页签和按钮分组重复表达当前工作上下文。
- UI 控件被业务模块直接引用，并存在多个控件别名，继续追加功能会增加维护风险。

本次重构不是视觉换肤，也不是重写业务算法，而是先合并功能入口，再重新建立信息架构、交互规则和适度统一的视觉体系。

## 2. 已确认决策

- 采用“左侧主导航 + 中央地图 + 右侧上下文面板”的整体结构。
- 功能和数据行为保持不变，项目文件格式保持兼容。
- 采用混合式交互：默认突出推荐下一步，同时允许熟练用户展开高级操作或跳转到其他阶段。
- 视觉方向为克制的现代专业风格：浅灰背景、白色工具面板、蓝色主操作和清晰状态色。
- 最低适配普通笔记本 `1366 x 768`，外接显示器主要增加地图和上下文面板空间，不改变操作结构。
- 正常状态保持安静，异常、未保存和待确认状态才突出显示。
- 流向辅助不再保留原有按钮集合后重新排版，而是按能力合并入口。
- DEM 是预览结果的审核工具，不是独立的流向生成流程。
- 继续使用 Tkinter + ttk，不迁移 PyQt，也不在本阶段引入新的 UI 框架依赖。

## 3. 目标与非目标

### 3.1 目标

- 一个能力只保留一个主要可见入口。
- 相同结果的操作采用一致的动词和命名。
- 页面根据当前任务和状态显示必要控件。
- 所有可增长的右侧内容均可滚动，不再发生控件不可达。
- 用户可以清楚区分编辑、预览、审核和应用。
- 河道与流向两条核心工作流保持高效，不因引导流程增加无意义点击。
- UI 构建、命令定义、状态呈现和业务回调形成明确边界。
- 为后续 V2.3 和 V3.0 功能扩展预留稳定入口。

### 3.2 非目标

- 不修改河道栅格、FDR、DEM 或 SHP 的计算算法。
- 不修改 ASC 导出格式和头信息保留规则。
- 不修改现有项目文件和自动保存文件的兼容策略。
- 不实现网页式动画、半透明面板或复杂主题切换。
- 不在本次重构中新增业务功能。

## 4. 整体信息架构

### 4.1 顶部全局命令栏

顶部只保留不依赖当前任务的命令：

- 打开项目
- 保存项目
- 导出 ASC
- 撤销
- 重做
- 适配内容
- 居中河流线
- 缩放
- 自动保存状态

“河道订正/流向订正”不再在顶部重复显示。当前任务由左侧主导航唯一决定。

### 4.2 左侧主导航

左侧只保留稳定的工作入口：

1. 河道订正
2. 流向订正
3. 显示与配色
4. 历史与恢复

项目与数据通过顶部入口打开独立面板或对话框，不长期占用地图左右空间。

笔记本宽度下左侧导航保持紧凑；外接显示器下可显示完整文字。导航变化只切换上下文，不直接修改数据。

### 4.3 中央地图区

中央地图继续承载现有栅格、河流线 SHP、汇流范围 SHP、流向箭头、预览和 DEM 评分覆盖层。

鼠标行为保持统一：

- 左键：执行当前编辑工具。
- 右键单击：选中像元。
- 右键拖动：框选区域。
- 中键拖动：平移地图。
- 滚轮：缩放地图。

地图左上角只显示简短上下文，例如当前任务、当前工具、方向和缩放级别。

### 4.4 右侧上下文面板

右侧面板只显示当前导航任务需要的控件，并具备统一垂直滚动能力。

参数、说明和审核结果位于可滚动内容区；当前阶段的主要操作区固定在面板底部，不随动态提示被挤出可视范围。

面板顶部显示当前任务摘要：

- 当前工具或当前辅助阶段
- 已锁定像元数量
- 出口是否已设置
- 是否存在待应用预览
- 是否存在警告或错误

详细文件路径、完整日志和低频设置不在摘要中长期显示。

### 4.5 底部状态栏

底部状态栏显示：

- 坐标
- 栅格行列号
- 像元值
- 流向文字
- 最近一次操作结果
- 未保存、错误或待确认状态

普通成功信息短暂显示；需要用户处理的问题保持显示，直到问题解除或用户明确关闭。

| 地图导航 | 顶部地图工具 | 适配、居中、缩放和平移不进入具体订正页 |

| 河道批量修正 | 河道订正 / 按河流线修正 | 选择后才显示矢量容差和执行操作 |
| 流向人工编辑 | 流向订正 / 手动编辑 | 方向、画笔大小和方向建议集中显示 |
| 订正对象选择 | 流向订正 / 辅助订正 / 订正对象 | 地图框选、单像元追加和范围 SHP 作为选择方式，不作为并列主流程 |

| DEM 评估 | 流向订正 / 辅助订正 / 结果审核 | 只审核当前预览，提供评估、筛选、定位和报告 |
| 预览应用 | 流向订正 / 辅助订正 / 结果审核 | 应用预览、清除预览和重置辅助状态明确分离 |
| 显示开关和颜色 | 显示与配色 | 分为显示开关、颜色和配色预设三个区域 |
| 撤销和重做 | 顶部全局命令 | 高频操作常驻 |
| 快照和恢复 | 历史与恢复 | 统一管理快照、自动保存恢复和历史信息 |

## 6. 河道订正交互

河道订正页只保留两类能力。

### 6.1 手动工具

- 画笔
- 橡皮擦
- 画笔大小
- 快捷键设置入口

手动编辑直接修改河道栅格，并继续进入现有撤销、重做、日志和快照机制。

### 6.2 按河流线修正

该区域默认收起低频参数。用户展开后可设置矢量容差并执行批量修正。

批量修正仍使用现有算法，不改变默认容差和写入结果。

## 7. 流向订正交互

流向订正先区分两个工作方式。

### 7.1 手动编辑

显示：

- 当前 D8 方向
- 方向选择
- 画笔大小
- 建议方向
- 当前选中像元信息

左键继续直接写入所选方向，右键继续只选择像元。该区域不显示锁定河道、出口、汇流或 DEM 缓存按钮。

### 7.2 辅助订正

辅助订正采用四阶段主流程：

1. 订正对象
2. 方向生成
3. 结果审核
4. 应用结果

#### 7.2.1 订正对象

选择方式：

- 地图框选
- 单像元追加
- 汇流范围 SHP

主操作统一为“加入订正对象”。

“移除所选河道”和“重置订正对象”属于次要或高级操作。锁定结果仍使用现有锁定像元集合，不改变底层语义。

#### 7.2.2 方向生成

预览目标：

- 河道本体
- 周边汇流

选择河道本体时显示出口和河道方向模式；选择周边汇流时显示汇流方式、近带、远带和最大距离。

两种目标统一使用“生成预览”。预览不修改 FDR。

#### 7.2.3 结果审核

显示：

- 待修改像元数量
- 已一致像元数量
- 当前预览目标
- DEM 缓存覆盖率
- 顺坡、平坦、逆坡和无 DEM 数量
- 逆坡冲突等级

DEM 区域只在存在预览时可用。加载 DEM 和生成缓存属于审核准备操作；评估、定位冲突、筛选和导出报告属于审核结果操作。

“加载 DEM”只有一个稳定命令。审核页在 DEM 缺失时可按需显示该命令的上下文入口，但不创建第二套回调或长期并列入口。

#### 7.2.4 应用结果

- 应用预览：把待修改预览写入 FDR，并创建历史记录。
- 清除预览：只清除临时预览，不清除订正对象和出口。
- 重置辅助状态：清除订正对象、出口和预览，不回滚已应用数据。

当不存在待修改预览时，不突出显示“应用预览”。

## 8. 命名规范

### 8.1 基本规则

- 命令使用“动词 + 对象”。
- 同一动词保持一致语义。
- “预览”永远不写入数据。
- “应用”表示把预览结果写入当前栅格。
- “清除”只移除临时内容。
- “移除”只从集合中删除所选对象。
- “重置”表示清空当前辅助任务状态，不回滚已应用数据。
- 会修改数据的动作明确写出对象，避免使用含义模糊的“确定”“处理”“执行”。
- 参数名称在界面空间允许时标明单位，例如“近带（像元）”。
- 按钮保持短名称，完整影响范围通过悬浮提示说明。

### 8.2 建议替换表

| 当前名称 | 新名称 | 说明 |
| --- | --- | --- |
| 订正河道 | 河道订正 | 与左侧任务名称一致 |
| 订正流向 | 流向订正 | 与左侧任务名称一致 |
| 加载河道 | 加载河道 ASC | 明确文件类型 |
| 加载流向 | 加载流向 ASC | 明确文件类型 |
| 加载SHP | 加载河流线 SHP | 区分线和面 |
| 加载汇流范围 | 加载汇流范围 SHP | 明确用途和文件类型 |
| 适配窗口 | 适配内容 | 当前操作会选择适配对象 |
| 居中SHP | 居中河流线 | 避免使用文件格式代替业务对象 |
| 快照 | 创建快照 | 明确动作 |
| 恢复自动保存 | 恢复自动保存会话 | 明确恢复对象 |
| 应用方向 | 写入所选方向 | 明确会修改当前像元 |
| 断点建议 | 建议方向 | 名称更自然，完整逻辑由提示解释 |
| 矢量批量修正 | 按河流线修正 | 使用业务对象名称 |
| 锁定选区河道 | 加入所选河道 | 纳入“订正对象”统一语义 |
| 补锁单像元 | 加入所选像元 | 避免内部实现词“补锁” |
| 锁定范围内河道 | 加入范围内河道 | 与选择方式一致 |
| 清除选区 | 移除所选河道 | 明确只影响当前选择范围内的订正对象 |
| 设为出口 | 设为下游出口 | 明确方向语义 |
| 预览河道流向 | 生成预览 | 预览目标选择为“河道本体” |
| 预览周边汇流 | 生成预览 | 预览目标选择为“周边汇流” |
| 清除当前预览 | 清除预览 | 当前上下文已明确 |
| 清空锁定 | 重置辅助状态 | 明确会同时清除订正对象、出口和预览 |
| 加载DEM | 加载 DEM | 统一中英文间距 |
| 生成锁定范围缓存 | 生成 DEM 缓存 | 缓存范围通过状态摘要说明 |
| 评估当前预览 | 使用 DEM 评估预览 | 明确评估依据 |
| 定位逆坡冲突 | 定位下一处逆坡 | 表达循环定位行为 |
| 导出评估报告 | 导出 DEM 评估报告 | 明确报告类型 |
| 导出冲突报告 | 导出逆坡冲突 | 明确导出内容 |
| 恢复默认颜色 | 恢复默认配色 | 与配色预设术语一致 |

命名替换在实现时需同步更新悬浮提示、状态栏消息、使用说明和测试断言。

## 9. 信息和状态语义

### 9.1 颜色

- 蓝色：当前操作和主要命令。
- 绿色：正常、已加载、已完成。
- 黄色：待确认、待应用、覆盖不足但可继续。
- 红色：错误、严重冲突、操作失败。
- 灰色：普通信息、未开始、禁用。

颜色不是唯一提示方式，所有状态同时使用文字或图标，避免仅依赖颜色判断。

### 9.2 信息层级

1. 异常和阻断问题。
2. 待确认或待应用状态。
3. 当前任务和下一步操作。
4. 正常文件状态和详细路径。
5. 历史日志和低频信息。

前三级可进入主界面；后两级按需查看。

## 10. 视觉和响应式约束

- 界面最低支持 `1366 x 768`。
- 左侧导航保持紧凑，并允许在笔记本宽度下缩窄。
- 右侧上下文面板使用可调宽度，默认约 `340-380` 像素。
- 地图区具有最小宽度保护。
- 所有右侧任务页使用统一滚动容器。
- 动态提示不得改变主按钮可达性。
- 当前阶段的主要操作区固定在右侧面板底部，可滚动内容不得覆盖或挤出该区域。
- 使用系统可用的中文 UI 字体和 ttk 控件，不依赖网络字体。
- 控件高度、分组间距、标题层级和禁用样式由统一 `ttk.Style` 管理。
- 图标使用本地资源并附带文字或悬浮提示，不使用图标替代不熟悉的业务概念。

## 11. 技术结构

建议新增或明确以下 UI 层边界：

### 11.1 UI Shell

负责顶部命令栏、左侧导航、中央地图、右侧上下文面板和底部状态栏，不包含 GIS 业务计算。

### 11.2 UI Components

提供可复用组件：

- 可滚动任务面板
- 导航项
- 任务摘要
- 状态提示
- 参数行
- 主操作区
- 高级操作折叠区

### 11.3 Command Registry

为每个用户命令定义：

- 稳定命令 ID
- 显示名称
- 回调
- 启用条件
- 是否修改数据
- 悬浮提示

业务模块不再依赖同一按钮的多个属性别名。过渡阶段可保留兼容映射，但新代码只使用稳定命令 ID。

### 11.4 Status Presenter

将现有模式、工具、流向辅助、DEM、自动保存和错误信息转换为统一状态模型，再由任务摘要和底部状态栏显示。

### 11.5 业务层

现有河道编辑、流向辅助、DEM、渲染、项目保存和历史模块继续提供业务能力。UI 重构通过已有方法调用业务层，不复制算法。

## 12. 状态流和错误处理

### 12.1 状态流

用户命令通过 Command Registry 调用现有业务方法。业务方法更新现有数据状态后，统一触发：

1. 刷新命令启用状态。
2. 刷新任务摘要。
3. 刷新地图覆盖层。
4. 发布短暂成功消息或持久警告。

### 12.2 错误处理

- 缺少必要文件：在任务摘要中显示缺失对象和加载入口。
- 预览前置条件不足：禁用主操作并通过悬浮提示说明原因。
- DEM 缓存失效或覆盖不足：显示黄色警告，不自动覆盖 FDR。
- 后台任务失败：显示红色错误，保留重试入口。
- 未保存退出：继续使用现有退出确认和自动保存策略。
- UI 页面切换不得隐式清除预览、锁定对象或未保存编辑。

## 13. 兼容性

- 项目和自动保存中的现有字段继续读取。
- 快捷键继续生效；按钮改名不改变快捷键绑定。
- 原有编辑历史、日志和快照行为保持不变。
- 新 UI 状态可新增项目字段，但必须提供缺省值并兼容旧项目。
- PyInstaller 打包仍使用现有 Python/Tkinter 路线。

## 14. 实施分期

### 阶段 1：命令和状态边界

- 建立命令 ID、显示名称和启用条件。
- 清理新代码对控件别名的依赖。
- 为命令和状态规则增加自动测试。
- 不改变现有界面布局。

### 阶段 2：全局 Shell 和河道订正

- 实现顶部、左侧、地图、右侧和底部框架。
- 接入河道订正、显示和项目入口。
- 验证笔记本分辨率和地图交互。

### 阶段 3：流向订正和 DEM 审核

- 分离手动编辑和辅助订正。
- 合并订正对象和预览入口。
- 将 DEM 纳入结果审核。
- 统一预览应用和清理语义。

### 阶段 4：历史、配色和回归

- 整理历史恢复、显示配色和项目状态。
- 更新悬浮提示和使用说明。
- 执行完整工作流和打包回归测试。

## 15. 测试与验收

### 15.1 自动测试

- 命令 ID 到回调的映射。
- 命令启用条件。
- 流向辅助各阶段状态转换。
- 清除预览、移除订正对象和重置辅助状态的作用范围。
- 项目保存和自动保存对新增 UI 状态的兼容。
- 1366 x 768 布局尺寸计算和滚动容器行为可测试部分。

### 15.3 验收标准

- 右侧任何动态信息都不会使按钮不可达。
- 主要操作始终在右侧固定操作区可见，低频内容通过滚动访问。
- 同一能力不存在多个并列主要入口。
- 用户能明确区分手动编辑、辅助预览、DEM 审核和最终应用。
- 清除、移除、重置和应用的影响范围与文案一致。
- 现有数据结果和项目工作流不发生回归。
- 在 `1366 x 768` 下所有主要工作流可完成。
