# V2.2 需求池

本文用于记录 V2.1.0 发布后的候选需求和维护方向。它不是立即开发计划，后续每次开始 V2.2 功能前，应先从本文挑一个明确的小闭环，不要一次性把所有候选项混在一起做。

## 1. 当前版本基线

当前稳定版本：

- `v2.1.0`
- 已完成本地回归测试。
- 已完成 EXE 打包和 GitHub Release。
- 已有 V2.1 发布说明、工作流测试清单和打包发布清单。

V2.2 开发前建议先确认：

- 当前 `main` 没有未提交改动。
- `docs/V2.1工作流测试清单.md` 仍能跑通。
- 新功能不会破坏 V2.1.0 的河道订正、流向订正、范围 SHP 汇流和配色管理主流程。

当前 V2.2 起步项：

- 已完成基础版：流向辅助状态提示增强，在操作提示区和流向辅助区显示下一步建议。
- 已完成基础维护：将流向辅助状态提示逻辑拆入 `water_flow_status.py`，减少 `water_app.py` 职责。
- V2.3 候选方向 DEM 辅助已单独建档，不混入 V2.2 小步维护。

## 2. 功能候选

### 2.1 汇流范围 SHP 增强

优先级：高

背景：

V2.1 已支持加载汇流范围面 SHP、显示边界、锁定面内河道、按面范围预览周边汇流。后续可以继续提升“面内汇流”的可控性。

候选点：

- 面范围内所有候选栅格向已锁定河道汇流。
- 支持用户指定目标河道，只让面内像元汇入指定锁定河道。
- 面内存在多条锁定河道时，默认汇入最近河道，但允许人工覆盖。
- 对“已有流向是否覆盖”提供策略选项：
  - 只修改方向不一致像元。
  - 覆盖所有候选像元。
  - 只预览不写入，由用户局部筛选。
- 复杂 multipart、多孔 polygon 暂不急于完全支持，优先保持当前简单面范围稳定。

建议实现方式：

- 不替代当前近远带模式，作为并列模式继续保留。
- 预览仍区分橙色需修改和蓝色已一致。
- 应用时只写入橙色预览结果。
- 大范围面处理要注意性能，必要时按视窗或分块处理。

### 2.2 流向辅助交互精简

优先级：中高

候选点：

- 继续优化“锁定河道 -> 设出口 -> 预览河道流向 -> 应用 -> 预览周边汇流 -> 应用”的操作提示。
- 在操作提示区显示当前锁定河道数量、出口状态、预览类型和可应用数量。已在 V2.2 起步项中完成基础版。
- 预览前如果缺少锁定河道或出口，给出更明确提示。
- 对“清除选区”和“清空锁定”增加更清楚的按钮文字或二次确认。已完成基础文案调整。

目标：

让新用户不看说明也能知道下一步该点什么。

### 2.3 配色管理继续完善

优先级：中

V2.1 已完成：

- 显示开关、颜色编辑、配色预设分组。
- 颜色和透明度编辑。
- 保存、加载、删除预设。
- 恢复默认颜色。

候选点：

- 增加预设重命名。
- 增加导入/导出配色预设 JSON。
- 增加几个内置主题，例如“浅色默认”“高对比”“打印检查”。

### 2.4 打包流程优化

优先级：中

背景：

V2.1 打包成功，但 `--clean` 打包较慢，原因之一是当前 spec 收集了较多 NumPy/SciPy 测试模块，并间接牵出 matplotlib/PyQt5 等不必要依赖。

候选点：

- 收窄 PyInstaller hiddenimports，减少测试模块和无关库收集。
- 增加 excludes，例如 matplotlib、PyQt5、pytest、numpy/scipy tests，前提是充分验证 EXE。
- 保留当前可用 spec 作为稳定打包配置，不直接破坏已验证路径。
- 若优化 spec，应单独提交，并重新执行 EXE smoke test。

### 2.5 代码维护继续拆分

优先级：中

当前 `water_app.py` 仍然较大。V2.2 前后可以继续拆：

- 已拆：`water_flow_status.py`，承接流向辅助状态摘要、下一步建议和应用按钮动态文案。
- `water_flow_workflow.py`：锁定、出口、预览、应用、清理。
- `water_flow_render.py`：流向辅助标记和预览绘制。
- `water_render_cache.py`：视窗渲染缓存和脏区刷新协调。
- `water_dialogs.py`：弹窗和复杂 UI 组件。

原则：

- 每次只拆一个职责。
- 拆完必须跑 smoke test。
- 不在重构提交里混入新功能。

### 2.6 DEM 辅助流向订正

优先级：V2.3，不纳入 V2.2 主线

说明：

用户后续可能提供 30m DEM，希望作为流向订正的辅助依据。但 DEM 数据量大、分辨率和当前 ASC/FDR 不一致，不能直接整体加载或自动替换现有流向。

该方向已单独记录在：

- `docs/V2.3_DEM辅助方案.md`

V2.2 期间只保留方案讨论，不建议直接开始实现。除非用户明确切换到 V2.3 开发，否则 V2.2 仍以交互、维护和稳定性为主。

## 3. 暂不建议立即做

- 完全自动化流向修正。
- 完整 DEM 级水文分析。轻量 DEM 辅助已作为 V2.3 候选方案单独记录。
- 全国范围自动纠错。
- 复杂 polygon 拓扑语义完全支持。
- 多人协作和 Git 集成编辑工作流。
- 大规模 UI 框架迁移。

这些方向不是不能做，而是会明显增加复杂度，不适合作为 V2.2 的第一批小步迭代。

## 4. 建议的 V2.2 起步顺序

1. 先做一个小的交互增强，例如操作提示区显示锁定数量、出口和预览状态。
2. 再做面范围汇流的“指定目标河道”原型。
3. 原型稳定后，再决定是否优化打包 spec。
4. 每完成一项都跑 V2.1 工作流测试清单中相关部分。

## 5. 每次开工前检查

- 是否会影响 V2.1.0 主流程？
- 是否需要新增回归测试条目？
- 是否需要更新 `docs/项目总说明.md`？
- 是否需要更新 README？
- 是否应单独提交？

如果答案不确定，先讨论方案，不直接改代码。
